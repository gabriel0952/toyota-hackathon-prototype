# 工程決策表與團隊檢核

規則檔：`services/decision-api/decision_api/rulebook.json`。ruleVersion 帶內容 hash；來源回應也依內容 hash 保存。以下是待業務驗證的工程假設，不是 Toyota 官方承諾。

| 項目 | 目前規則 | 需團隊確認 |
|---|---|---|
| 綠燈 | 家／工作充電已可用，必要行程通過 | 「可用」的證據及更新期限 |
| 裝樁黃燈 | 固定車位＋安裝初評通過＋行程通過 | 社區、配電、施工評估細項 |
| 公充黃燈 | 覆蓋區域、相容接頭、符合時段的主站與備援至少 2 站＋行程通過 | 主站、備援距離與實際開放條件 |
| 黃燈排序 | 綠先；偏好公共且公共成立時優先公共，否則裝樁先 | 偏好與排序是否符合服務邏輯 |
| 灰燈 | 已知行程限制使所有路徑不成立，或所有補電方案已知不可行 | 何時可判定所有替代方案已查明 |
| 待確認 | 未知關鍵條件／區域未覆蓋；不當成灰燈 | 必填／選填的最小判斷集合 |
| 行程 | 工程可用里程 300 km；長途超出往返範圍需目的地備援、至少 30 分鐘停靠，單程上限 600 km | 目標年式、路線、SOC、天氣等；30 分鐘不是充電時間保證 |
| 費用 | 月里程 × 18 kWh/100km ÷ (1−10%損失) × 電價範圍 | 能耗、充電比例、費率；未提供油資不比較省多少 |
| 阻力 | 四類：穩定補電、公共備援、行程、成本；分數排序取 Top 3 | 分數是規則指標，不是換購機率；待確認權重 |
| 資料完整度 | 依 rulebook 的固定欄位集合計算 provided／not_applicable 比例；未提交也算缺漏 | 不把完整度視為購車成功率 |
| 區域 | 台北內湖／南港、台中西屯，另有「示範無站區」反例 | 正式來源與覆蓋驗證；目前精確比對行政區文字 |

- [ ] 團隊指定規則檢核人與正式車款年式。
- [ ] 確認初評、可用、充電時段与備援的證據要求。
- [ ] 用真實官方資料檢核能耗／費率，定義有效期。
- [ ] 確认無站與未覆蓋回應的產品文案。
- [ ] 正式串接前版本化核准規則與拒絕／待確認案例。

目前刻意不猜测任意區域、不用充電峰值保證停靠時間，也不在未收到條件變動時猜测使用者生活狀態。

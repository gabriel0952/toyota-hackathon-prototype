# Phase 2 本機操作腳本

先啟動 8000 後端與 4174 API 前端（參考 README），使用虚構資料。

1. 車主瀏覽器進入 `/driver`，開始診斷。車款可使用顯示預設或自行修改。
2. 停車頁展開選填：住家／公司充電皆「無法使用」、安裝「無法安裝」、公共充電「白天」、住家「台北市內湖區」。補電偏好維持公共。
3. 行程選「幾乎沒有」長途。能源填月里程 1200、油資 4800，完成評估。
4. 應顯示公共黃燈 actual v1；來源清楚標為種子與工程假設。記下 family URL。
5. 點「條件模擬」再模擬家充可用：建立 simulation v2；原 actual v1 不變。
6. 同意分享給示範顧問。另一瀏覽器工作階段開 `/advisor` 並按本機顧問登入。
7. 顧問進入已授權報告、勾選家充「已實際可用」、更新條件。建立 actual v3。新增測試服務筆記。
8. 車主及 `/line/result/{familyId}` 在可見頁面輪詢或重新進入後顯示 v3；歷史 v1 可讀，公開 response 沒有筆記。
9. 車主撤銷分享；顧問下一次載入／輪詢顯示無授權，名單不再包含該報告。

補充反例：全部充電狀態已知不可行，住家區域「示範無站區」可形成灰燈；住家區域留白或未覆蓋、且沒有其他可行條件時為待確認。家充可用但長途單程 700 km、每週、30 分鐘停靠、目的地台中西屯，依工程規則仍是灰燈，不能把家充模擬說成必定轉綠。

若重評工具失敗，已保存 revision 與舊報告分開保留；畫面顯示待評估，原按鈕可用同請求重試。409 時先重新載入最新版再確認，勿反覆送出過期條件。

## 接續 M4 前需要確認

- 指定目標行政區、bZ4X 年式與官方來源引用／更新日期。
- 核對 TDX 接頭、時段、站點／接頭識別、授權、更新頻率、覆蓋與故障回應。
- 取得可用且經授權的內部資料；確認 RAG 查詢範圍與資料分級。
- 選定 LLM、金鑰管理及允許工具，維持數值／路徑由規則決定。
- 核准 rulebook 工程門檻，再新增外部資料 adapter；此次實作未發出外部查詢或通知。
